# Embedded Browser (`src/main/lib/embeddedBrowser/`)

> In-app browser shown as a resizable side panel beside the chat, **scoped per chat session**. Clicking an http/https link in a chat message opens it here (in that session's own view) instead of the system default browser. Each chat session gets its own native Electron `WebContentsView` owned by the main process, so different agents' browsing never interferes. The renderer only draws the panel chrome and reports the placeholder bounds. The browser loads **no** Chrome extensions (see Architecture → "No browser extensions").
>
> The same per-session view is also **agent-controllable**: the `browser` built-in tool (`mcpRuntime/builtinTools/embeddedBrowserTool.ts`) drives it to navigate, screenshot, read, click, type, and wait — gated by the per-profile `browser.enabled` switch in `profile.json` (toggled from **Settings → Browser**; default **off**). The same switch also controls visibility of the header Globe entry. When an agent drives it, the panel auto-opens so the user watches (see Architecture → "Agent automation").

## Architecture
- **Per-session views**: `views: Map<sessionId, {view, lastBounds, idleTimer}>`. Created lazily — a *new* chat session does NOT eagerly create a view; the view is created on the first link click (`open`) or when a panel for a session that has a remembered URL mounts (`show`). If a living view already exists for the session it is **reused**, never duplicated.
- **Three lifecycle states** per session:
  - *Foreground* — attached to `mainWindow.contentView`, bounds tracked. Exactly one session is foreground at a time (`foregroundSessionId`). `foreground()` defensively detaches any other attached view first, so two native views never overlap.
  - *Background* — detached when its panel unmounts (`hide`); a 5-minute idle timer (`IDLE_MS`) then destroys it. Reused instantly if the user returns before it fires (page + history preserved).
  - *Idle-reclaimed* — `webContents.close()`, removed from `views`. The session's last URL is kept in `lastUrls` so a later `show` recreates the view and reloads it.
  - *Purged* — `destroyAll()` closes every view and clears remembered URLs/bounds. This is the Settings -> Browser disable/teardown path, not the idle-reclaim path. `destroySession(sessionId)` performs the same cleanup for one deleted chat session.
- **Shared browsing data**: every view is created with `partition: 'persist:openkosmos-embedded-browser'`, so cookies, site data and cached images/files are shared across all sessions/tabs. Log in once in session A and session B is already authenticated.
- **Chrome identity**: every embedded browser view calls `webContents.setUserAgent()` before first navigation, and the shared embedded-browser partition rewrites outgoing http/https `User-Agent` plus UA Client Hints headers. The generated identity presents Google Chrome desktop while aligning the Chrome major/full version to Electron's embedded Chromium runtime; it switches the platform token between Windows and macOS, and maps high-entropy architecture hints to `arm` or `x86` when a site requests them.
- **No browser extensions**: this module deliberately loads **no** Chrome extensions. An earlier iteration bundled the Microsoft Single Sign On extension to enable silent work/school SSO, but it was removed because its core mechanism — Chrome native messaging (`chrome.runtime.sendNativeMessage` to `com.microsoft.browsercore`) — is **not supported by Electron** (see [findings doc](../../../../ai.prompt/embedded-browser-sso-findings.md)). If SSO is needed in future, do it at the Electron `session` layer (shared cookie partition / WAM / `app.on('login')`), not via a store extension.
- **Native view, not `<webview>`**: a `WebContentsView` always floats above the renderer DOM. Backgrounding calls `removeChildView` so it never covers chat.
- **Bounds handshake**: the renderer (`EmbeddedBrowserPanel.tsx`) measures its placeholder div with `getBoundingClientRect()` and pushes `{sessionId,x,y,width,height}` via `embeddedBrowser:setBounds`. Values are DIPs (CSS pixels) relative to the window content area — passed straight to `WebContentsView.setBounds`, **no devicePixelRatio scaling**. Bounds are cached by session even if they arrive before async view creation finishes, then applied when the view is foregrounded. A `ResizeObserver` + window `resize` listener keep it aligned during divider drags, window resizes, and sidebar toggles.
- **Navigation state push**: `did-navigate*`, `page-title-updated`, `did-start/stop-loading` are forwarded to the renderer (`navStateChanged`, carrying `sessionId`) so the panel routes them to the right per-session state entry.
- **Loading affordance**: while `isLoading` is true the panel shows an **indeterminate** progress bar pinned to the toolbar's bottom edge (`.embedded-browser-progress` in `globals.css`) and swaps the **Reload** button (`RotateCw`) for a **Stop** button (`Square` → `stop(sessionId)` → `webContents.stop()`). Electron exposes no load-percentage event, so the bar is animated, not a real fraction. The bar must live in the toolbar chrome, not the surface placeholder — the native `WebContentsView` floats above the surface and would cover it. `reload`/`stop` optimistically set `isLoading` in the atom so the toggle/bar react instantly; the main-process `did-start/stop-loading` events reconcile the true state.
- **Security**: each view uses `contextIsolation: true, sandbox: true` and does NOT load the app preload. Popups inside the browsed page go to `shell.openExternal` (own `setWindowOpenHandler`) to avoid recursive panels.
- **Scope / entry points**: the panel opens either from a chat-message link click (`StreamingV2Message.tsx`, `IncrementalMarkdownRenderer.tsx`, only when a `currentChatSessionId` is set) or from the header Globe toggle (`ChatViewHeader.tsx` → `actions.toggle`). Once open, the address bar can navigate to any allowed http/https URL. Page-initiated public http/https popups use the system browser; unsupported protocols remain outside the embedded-browser navigation boundary.
- **Agent automation** (the `browser` built-in tool): the manager exposes a small automation API consumed by `mcpRuntime/builtinTools/embeddedBrowserTool.ts`:
  - `ensureViewForAutomation(sessionId, url?)` — create-or-reuse + foreground the view, **clear the idle timer** so it isn't reclaimed mid-task, best-effort enable CDP Network capture before any automation navigation (navigation must continue if another debugger already owns CDP), reload the remembered URL if it was reclaimed since last turn, and fire `panelOpenRequested` so the renderer auto-opens the panel. Loading waits honor the caller's `AbortSignal` and stop the webContents on cancellation. Resolves with the current `EmbeddedBrowserNavState`.
  - `captureScreenshot(sessionId, rect?)` -> `webContents.capturePage(rect).toPNG()` as **raw base64** (no `data:` prefix). The tool wraps it as `{type:'image',data,mimeType}`; the turn runner detects that shape, strips the base64 from the transcript, and injects a vision message so the agent sees the page. The tool **gates** this on `hasNavigablePage(sessionId)` first: a fresh, never-navigated session has no page, so the tool fails cleanly ("navigate first") **without** calling `ensureViewForAutomation` — it does not fabricate a blank view or auto-open the panel just to error. As a defensive net, `captureScreenshot` itself also throws when `view.getBounds()` is 0x0 (a 0x0 view has never composited, so `capturePage()` would only yield an empty PNG). `screenshot` can also apply `viewport="desktop"|"mobile"`, explicit bounded `width`/`height`, `fullPage=true`, or a locator crop; temporary viewport changes are restored after capture. Visual baselines store raw screenshot base64 only in a bounded in-memory LRU-style cache (32 entries / 25 MiB) and are cleared on `destroySession` / `destroyAll`; `compare_visual_baseline` can report diff metadata, but nested diff PNG base64 is intentionally omitted because only top-level image tool results are vision-injected and transcript-scrubbed.
  - `hasNavigablePage(sessionId)` → `views.has(sessionId) || lastUrls.has(sessionId)`. Cheap predicate the `browser` tool uses to decide whether `screenshot` has anything to capture (live view, or a remembered URL an idle-reclaim left behind) before doing any view/panel side effects.
  - `executeJs(sessionId, expr)` → `webContents.executeJavaScript(expr, true)`; used for `read_page`, accessibility-like `inspect`, richer `diagnostics`, element resolution, focus, `wait_for` existence checks, window/container scrolling, clearing fields, selecting options, paste focus, and full-page screenshot sizing.
  - `ensureDebugger` / `sendCdpCommand(sessionId, method, params)` — attach the Chrome DevTools Protocol debugger (`webContents.debugger.attach('1.3')`, guarded by `isAttached()` + the per-view `debuggerAttached` flag) and dispatch **trusted** input (`Input.dispatchMouseEvent`, `Input.insertText`, `Input.dispatchKeyEvent`, `DOM.setFileInputFiles`, `Accessibility.getFullAXTree`, `Network.enable`). Trusted events survive React's synthetic-event handling and `isTrusted` checks; synthetic JS events would not. `click`, `double_click`, `right_click`, `hover`, `type`, `clear`, `select_option`, `multi_select`, `upload_file`, `set_slider`, `set_date`, assertions, and `screenshot` support expanded locators: CSS selector, visible text where appropriate, role, accessible name, label, placeholder, test id, one same-origin iframe selector, and one open shadow-root host selector. Frame and shadow scopes fail closed if the requested same-origin frame or open shadow root is missing/inaccessible; scoped locators must never fall back to the top-level document. `accessibility_snapshot` caps the returned AX tree to 200 nodes and truncates long strings to keep tool output bounded. `drag` dispatches trusted mouse events from `sourceSelector` to `targetSelector`; `scroll` supports locator targets plus pixel, edge, and percentage modes. Network diagnostics capture `requestWillBeSent`, `responseReceived`, and `loadingFailed` CDP events with request metadata from the initial automation navigation onward, redact credential-bearing request/response headers and sensitive URL query/fragments before storing diagnostics, and `assert_no_network_errors` checks both resource timing and captured CDP failures/responses. Download diagnostics omit local save paths. `destroyView` detaches the debugger first so it never leaks across recreation.
  - `open_local_file` starts/reuses a tokenized `127.0.0.1` preview server and serves the registered real file plus explicitly referenced same-directory relative assets, including `url(...)` dependencies inside linked CSS files, all confined by realpath to both the file's directory and the explicit trusted workspace root from tool execution context. Preview tokens are bound to the chat session and cleared by `destroySession` / `destroyAll`; full teardown also closes the localhost listener. Tokens must not expose unreferenced sibling files, parent-directory files, or symlink escapes. `upload_file` uses the same realpath workspace confinement before passing files to CDP. The browser still navigates to http/https only (plus `about:blank` as a safe blank bootstrap page); direct `file://` remains blocked.
  - `getDiagnostics(sessionId)` returns current URL/title/loading plus recent console, load-failure, and render-process-gone events captured per session. Normal main-frame `ERR_ABORTED` navigation cancellations are not persisted as load failures.
  - **Singleton accessor**: `initEmbeddedBrowserManager(getWindow)` is called once in `startup/ipc/index.ts` and stores the instance module-side; the tool (which runs outside that closure) reaches it via `getEmbeddedBrowserManager()`. Before this wiring the instance was block-scoped and unreachable — that was the lynchpin gap.
  - **Safety**: the tool itself never publishes/pays/deletes. High-impact/irreversible click targets, drag/drop endpoints, localized/unlabeled activation targets, and trusted keyboard activation/submission paths are refused; the browser tool does not accept model-supplied confirmation tokens or dispatch the action on retry. The agent must ask the user to perform the action manually or use `request_interactive_input` for explicit guidance.

## IPC Contract — `src/shared/ipc/embeddedBrowser.ts` (prefix `embeddedBrowser`)
- Renderer → Main: session-scoped calls `open(sessionId,url)`, `navigate(sessionId,url)`, `show(sessionId)`, `hide(sessionId)`, `setBounds(sessionId,bounds)`, `goBack(sessionId)`, `goForward(sessionId)`, `reload(sessionId)`, `stop(sessionId)` (aborts the in-flight load; the toolbar's reload button becomes a stop button while `isLoading`). `embeddedBrowserIPC.ts` validates renderer-controlled inputs before delegating: non-empty session IDs, http/https URLs, and finite non-negative bounds.
- Main → Renderer: `navStateChanged` (`EmbeddedBrowserNavState`, includes `sessionId`); `panelOpenRequested` (`EmbeddedBrowserPanelOpenRequest` `{sessionId,url}`) — fired by `ensureViewForAutomation` so the renderer auto-opens the panel for agent-driven sessions. The preload bridge whitelists only these two `embeddedBrowser:*` events and strips raw `IpcRendererEvent` before renderer callbacks.

## Common Changes
- **Add a toolbar control** (e.g. stop, home): add a method to the `RenderToMain` contract (first arg `sessionId` when session-scoped), the preload whitelist (`src/preload/embeddedBrowser/invoke.ts`), `EmbeddedBrowserManager`, `embeddedBrowserIPC.ts`, and a button in `EmbeddedBrowserPanel.tsx`.
- **Add an agent `browser` action**: add the case to `embeddedBrowserToolDefinition.ts`, the switch in `EmbeddedBrowserTool.execute`, tests in `embeddedBrowserTool.test.ts`, and a label to `getBrowserDisplayText` in `toolCallDisplayConfig.ts`. If it needs a new manager capability, add a method to `EmbeddedBrowserManager` and cover it in `EmbeddedBrowserManager.test.ts`. Keep returns JSON-able except for the `{type:'image',…}` screenshot shape.
- **Change the idle-destroy timeout**: edit `EmbeddedBrowserManager.IDLE_MS`. (Automation paths `clearIdle` while active; the timer is re-armed by the panel's `hide`.)
- **Persist panel width**: `EmbeddedBrowserAtom.width` is currently session-only (per app run, shared across chat sessions). Persist it through `appDataManager.updateConfig` if long-lived width preferences are added.

## Gotchas
- The native view floats above ALL renderer DOM, including overlays/modals. If a modal must appear above the browser, hide/offscreen the view while it is open.
- `setBounds` Y-coordinate is relative to the window content area; on macOS the custom title bar lives in the renderer, so `getBoundingClientRect().top` already accounts for it — do not add manual offsets.
- The panel is **keyed by `sessionId`** in `ChatSide`, so a session switch unmounts the old panel (→ `hide(old)`, backgrounding its view) before mounting the new one (→ `show(new)`). Do not remove the `key` — without it React reuses the component instance and the show/hide pairing breaks.
- Idle and nav-event callbacks may fire after a window/view is torn down; `emitNavState`/`detach`/`destroyView` guard with `isDestroyed()`.
- Session deletion calls `EmbeddedBrowserManager.destroySession(sessionId)` from `profile:deleteChatSession`, closing any live view and removing remembered URL/bounds entries for that session.
- Main-frame load failures are logged from `did-fail-load`; check for `EmbeddedBrowser` warnings before assuming the renderer panel itself is blank. `ERR_ABORTED` is a normal superseded-navigation cancellation and is intentionally ignored.
- **Agent automation — the `browser` tool is gated by a per-profile switch, not a feature flag.** `BuiltinToolsManager.initialize()` always registers the metadata, while public inventory accessors and execution read `profileCacheManager.getBrowserSettings(alias).enabled` live (persisted in `profile.json`, default **false**, toggled from Settings → Browser; the alias comes from the captured execution context or `getCurrentUserAlias()`). Enabling the switch mid-session immediately exposes the tool in the advertised inventory and allows execution; disabling it hides the tool and makes direct execution return the Settings → Browser disabled error. Chat-message http(s) link routing in streaming renderers also checks the same switch; disabled links keep normal anchor behavior instead of reopening the side panel. Disabling also purges runtime browser state immediately: the `profile:updateBrowserSettings` IPC handler calls `EmbeddedBrowserManager.destroyAll()` to close native `WebContentsView` instances and clear remembered URLs/bounds, and the renderer dispatches `embedded-browser:disable` so the root App bridge calls `EmbeddedBrowserAtom.closeAllAndDestroy()` to close every sidepane session state and invoke `embeddedBrowser:destroyAll`. The Agent page tool list only updates on toggle because `profileDataManager.handleProfileCacheUpdate` calls `mcpClientCacheManager.refresh()` when `browser.enabled` flips between the previous and next profile.
- **Navigation scheme allowlist is a security boundary.** Main-process navigation (`open`, `navigate`, and automation `loadAndWait`) accepts only `http:` and `https:` URLs, plus the safe empty page `about:blank` as an explicit blank-bootstrap exception. Never pass through `file:`, `data:`, `javascript:`, `ftp:`, or other schemes from the agent tool, renderer address bar, or IPC; those would bypass normal file-tool permission controls. The renderer IPC boundary (`requireWebUrl`) stays strictly http/https — `about:blank` is reachable only via the tool's `normalizeUrl` and the main-process `assertWebNavigationUrl`.
- **`about:blank` is an intentional bootstrap escape hatch (historical deadlock).** A real user session hung when the agent tried `navigate about:blank` to bootstrap a view: `normalizeUrl` mangled it into `https://about:blank`, which `assertWebNavigationUrl` then rejected as non-web, so the agent could never open a blank page. `normalizeUrl` now returns `about:blank` verbatim (case-insensitive) and `assertWebNavigationUrl` allows it, so the bootstrap navigation succeeds and drives the normal `panelOpenRequested`/bounds handshake. It is the ONLY non-http(s) target allowed; every other scheme (`mailto:`, `tel:`, `chrome:flags`, `file:`, …) is now rejected by `normalizeUrl` with a clear error instead of being silently rewritten to `https://…`.
- **Page-initiated main-frame navigation uses the same allowlist.** `WebContentsView` installs a `will-navigate` guard that prevents non-http(s) top-level navigations triggered by page links, scripts, redirects, or forms. Do not rely only on pre-load validation.
- **Agent automation is active-session only.** The renderer reports the current chat session via `embeddedBrowser:setActiveSession`. `ensureViewForAutomation` rejects non-active sessions before creating/foregrounding a native view and re-checks after navigation/readiness awaits. Screenshot, page JS, debugger attach, and CDP command paths also re-check before touching the page, so a session switch or chat-route unmount stops trusted automation before the next primitive.
- **The Settings switch is enforced at main IPC too.** `embeddedBrowserIPC` checks `profileCacheManager.getBrowserSettings(getCurrentUserAlias()).enabled` before every view-control method (`open`, `navigate`, `show`, `hide`, bounds, history, reload, stop). `destroyAll` and `setActiveSession` intentionally remain available while disabled for cleanup/bookkeeping.
- **Agent automation — singleton wiring and captured session are the lynchpin.** If `getEmbeddedBrowserManager()` returns null, the `browser` tool fails: confirm `startup/ipc/index.ts` calls `initEmbeddedBrowserManager(...)` (not the old block-scoped `new EmbeddedBrowserManager(...)`). `BuiltinMcpClient` captures `chatSessionId` before awaiting the lazy tool manager/import path and passes it through `BuiltinToolsManager.executeTool(..., chatSessionId)` into `EmbeddedBrowserTool.execute`; the tool must not re-read the mutable static execution context after an async boundary.
- **Agent automation — idle reclaim mid-task.** A view can be destroyed by the 5-min timer between turns; `ensureViewForAutomation` recreates it and reloads `lastUrls[sessionId]`, so every page-dependent action (`read_page`, `click`, `type`, `wait_for`, `screenshot`) must restore through it after checking `hasNavigablePage(sessionId)` rather than assuming the view survives. `navigate` and reclaimed-page reloads must pass the tool `AbortSignal` into `ensureViewForAutomation` so cancellation stops the in-flight `webContents.loadURL`.
- **Agent automation — debugger attach is exclusive & one-shot.** `webContents.debugger.attach` throws if a client is already attached (e.g. DevTools open). It is guarded by `isAttached()` + the `debuggerAttached` flag and detached in `destroyView`; never leak it across recreation.
- **Agent automation — auto-open must not double-navigate.** `revealForAutomation` only flips `isOpen` + mirrors the URL; it must NOT call `embeddedBrowserApi.open`, because the main-process view is already navigated by `ensureViewForAutomation`.
- **Agent automation — screenshot base64 has NO `data:` prefix.** The vision-injection path hashes the raw base64 for dedup; a stray prefix breaks dedup and the data URL it builds (`data:${mime};base64,${data}`).
- **Agent automation — screenshot-first on a fresh view fails cleanly, with no side effects, by design.** A brand-new session's `WebContentsView` is 0×0 until the renderer panel mounts and reports bounds (an async `panelOpenRequested` round-trip), and a 0×0 view has never composited, so `capturePage()` only yields an empty PNG. The tool's `screenshot` action therefore checks `manager.hasNavigablePage(sessionId)` **before** doing anything: if the session has no live view and no remembered URL, it returns `{ok:false,error:"…navigate first."}` **without** calling `ensureViewForAutomation` — so it does **not** create a blank `about:blank` view or fire `panelOpenRequested` (which would flash an empty browser panel at the user just to error). `captureScreenshot` keeps a defensive 0×0-bounds throw as a second line. An earlier attempt to *synthesize* a default viewport + double-rAF paint did **not** work (the rAF never fires on a non-compositing fresh view, so it hit the timeout and still captured 0 bytes) — do not reintroduce it; the clean gate is correct and consistent with `read_page`/`click`, which already require a page.
- **Do not reintroduce a Chrome store extension for SSO.** Electron does not support native messaging, so the Microsoft SSO extension (which relies on it) cannot function — see [findings doc](../../../../ai.prompt/embedded-browser-sso-findings.md).
